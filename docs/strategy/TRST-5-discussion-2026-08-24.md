## 2. 关键决策（按时间）

### 2.1 产品本质定位（最早锁定）
- **TrustOS = 个人 PC 的操作系统（本地 OS），不是云操作系统**。
- 大模型与系统 = 安装在本机上的应用软件。
- TRST-5 目标 = 像 PC OS 只做三件事：**支持（兼容/驱动应用） + 性能优化 + 安全（本机数据保护）**。
- 多租户（5C）明确剔除（本机单用户）。

### 2.2 数据隔离已存在，新规划必须复用
- Boss 提示：manager+worker 的数据隔离已通过架构实现。
- 代码审计确认：`local-manager-runtime.ts` / `manager-view.ts` / `context-package.ts` 已**代码级强制**
  artifact 不发 Manager、raw history/memory 不发两端、Worker 仅收 brief。
- 结论：5B 不重做隔离，只补**服务端身份合法性缺口**（X-User-Id 盲信 / permissions 自报 user_id）。

### 2.3 功能评估 → 重规划
- 13 项功能审计，三大冲突/不足：部署缺失(P0) / 安全未闭环(P0) / 前端破碎(P0)；
  前端性能薄(P1) / 监控半(P1)。企业卖点（Merkle 锚定/DLP/哈希链）不进 TRST-5。

### 2.4 竞争力方向：极客优先（本次核心决策）
- **目标用户：先服务愿自己跑容器的极客，小白后说。**
- **要有真的技术深度** —— 不削弱信任/审计/隔离架构，把极客看重的深度做透、做可见。
- **先解决以前开发的破碎问题**，让极客有真正体验（TSC_FAIL、孤儿 /v1/gateway 404、前端破碎）。
- **Memory 是用户粘性钩子**（Boss 明确："至少我是这么想"）：
  把 Memory 从 fixture 占位做成真实可用、随使用积累、迁移成本高的粘性核心。

## 3. 竞争力差异点（共识）

对极客真正成立的三条：

1. **本地优先 + 数据不出本机 + 可验证** —— 相对云端黑盒 AI 工作台的硬差异。
2. **真·审计引擎**（事件链+证据链+Ed25519 签名+合规锚定，MWT-4/4E/4F/4R 真实代码）
   —— 多数个人 AI 工具给不了"可验证的 AI 工作黑匣子"。
3. **Manager/Worker 隔离架构** —— 模型从根上不碰原始数据，隐私叙事有技术底座。

**共识**：竞争力不缺"弹药"，缺的是**让极客第一眼跑通、看见深度**。

## 6. 防反复护栏（Boss 意图）

1. 任何新功能先对齐"是否服务极客真实工作流 + 是否有真技术深度"，否则 HOLD。
2. 不复用已有能力时先查代码（manager+worker 隔离、MWT-6 引擎、Assessment 等已存在）。
3. 前端 TSC 必须保持绿；孤儿端点/组件接入前先确认后端路由真实存在。
4. Memory 作为粘性核心，其真实化优先级高于锦上添花的企业治理特性。
