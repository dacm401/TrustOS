## 5. 可探索的方向

### 方向 A：本地模型做 Manager ⭐（Boss 已明确）

**价值**：Manager 链路可做到**完全不出本机**——主权数据在本机，读取它的模型也在本机。这是 ADR-002 Phase 3 想法的完全体。

**关键挑战**：
- 小模型（1.5B~3B）的**路由决策能力**是否够用？
- 上下文短（8k）→ 注入预算必须严（已按 8k 设计）
- 需要 **benchmark 验证**：本地 Manager 的路由准确率 vs 云端，差距多大？

**建议路径**：先做**影子模式**——本地模型与云端模型同时决策，只记录对比，不影响线上。用数据证明可行性后再切换。

### 方向 B：用主权数据微调「懂我」的模型

**价值**：把积累的偏好/约束**内化**进模型，而非每次靠 prompt 注入（省 token、更稳定）。

**前提**：数据量积累到一定规模（当前还太少）。

**风险**：错误记忆会被固化进权重，且难以撤销——比 prompt 注入的错误**更难修复**。建议谨慎，且必须保留"原始记忆可编辑"的能力。

### 方向 C：主权数据的产品化呈现

**价值**：让用户**看见**自己的数据资产——"你积累了 N 条记忆、M 轮对话、覆盖 K 个主题，全部在你本机、可随时带走"。这是相对云端 agent 的**可视化壁垒**。

**成本**：主要是 UI 工作，技术风险低，差异化明显。

### 方向 D：可信执行的可视化

**价值**：每次回答都展示"用了哪些记忆 / 外发了什么 / 加工掉了什么"。把架构上的可信性**变成用户能感知的东西**。

**关联**：与方向 C 互补，都是"把内部能力外化为产品价值"。

### 方向 E（远期）：跨设备同步而不经云端

**思路**：P2P / 局域网同步主权数据包，保持"数据不出本机"的前提下实现多设备。

**注意**：这与"个人 PC OS"定位的契合度需 Boss 判断——可能超出当前范围。
