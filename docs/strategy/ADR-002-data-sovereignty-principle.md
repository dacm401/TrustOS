# ADR-002：数据主权原则（为什么必须在本机留存原文）

> **状态**：ACCEPTED（Boss 决策，2026-08-29）
> **决策者**：Boss
> **关联**：`ADR-001`（护栏重述）、`RFC-001`（主权数据战略与演进路线）
> **性质**：架构原则——后续所有涉及存储的决策都应与此一致

---

## 1. 决策

**原始 prompt 与对话数据必须在本机留存（加密），并以此作为"数据主权"的物理基础。**

配套原则：

| # | 原则 | 说明 |
|---|---|---|
| **1** | **加工解决「少泄露」，留存解决「谁拥有」** | 两者缺一不可；只加工不留存 = 唯一拥有数据的是云端 |
| **2** | **能带走的数据才是你的数据** | 必须支持打包、加密、导出、迁移；否则只是被锁定在这台机器 |
| **3** | **主权数据是演进资产** | 为本地模型读取（RAG → 微调）预留格式与接口空间 |
| **4** | **按敏感度分级，而非一刀切** | 与外发加工同一哲学：分级管理，不追求绝对 |
| **5** | **冷热分离**（2026-08-29 补充） | 使用中的数据**不加密**（保可检索）；归档数据**加密打包、长期保留**（不设保留期） |

---

## 2. 为什么（决策依据）

### 2.1 风险的不对称性（此前被算错）

| | 云端（大模型 App） | 本地 |
|---|---|---|
| 泄露状态 | **确定性**——已发生，每次输入都在别人服务器 | 可能性——需先入侵 |
| 控制权 | **零**——无法真删，可能被训练/审查/封号 | **完全**——可查可删可导出 |
| 访问者 | 提供商、传唤、模型训练 | 只有你 |
| 数据用途 | 训练别人的模型 | 只服务你 |

顾虑「本地存原文会被攻击」，却对「已发生且完全失控」的云端泄露习以为常——
这是**对可控的小风险过度警惕，对失控的大风险无感**。

### 2.2 旧护栏实际上削弱了架构

旧护栏「raw 不落库」与本架构的意图相矛盾：

```
若本地不留原文：
  本地 → 什么都没有（加工完即弃）
  云端 → 有你外发的每一次内容
  ⇒ 唯一拥有完整数据的一方，是你无法控制的一方
```

此时谈"自主权"是空话。

### 2.3 差异不在"更安全"，而在"主权归属"

大众用大模型 App 是因其**便利**（历史可查、上下文连续），这个便利是真实的。
TrustOS 的差异应表述为：

> **同样的可查询、同样的连续性，但数据在你手上。**

| | 大模型 App | TrustOS |
|---|---|---|
| 历史可查询 | ✅ | ✅（本地） |
| 上下文连续 | ✅ | ✅（Memory 蒸馏） |
| 数据可导出 | ❌ 或受限 | ✅ 完全 |
| 真正删除 | ❌ 不可验证 | ✅ 物理删除 |
| 被封号/破产 | 数据随之消失 | 与你无关 |
| 被用于训练 | ✅ 默认 | ❌ 不外发原文 |

### 2.4 粘性是结果，主权是理由

Boss 明确「Memory 是用户粘性钩子」。粘性的本质是**迁移成本**。
但若只有粘性而无主权，与使用大模型 App 无本质区别——只是换个地方被锁定。

## 3. 分层主权模型

| 层 | 内容 | 位置 | 谁控制 | 外发 |
|---|---|---|---|---|
| **L1 原始意图** | 完整 prompt、上下文、对话原文 | **本地（加密）** | 你 | ❌ 从不 |
| **L2 加工产物** | 脱敏/摘要后的 brief | 外发 → 云端留副本 | 你的加工规则 | ✅ 唯一外发层 |
| **L3 模型输出** | 返回结果 | 回落本地 | 你 | — |
| **L4 云端副本** | L2 的副本 | 云端（不可控） | 提供商 | — |

**关键**：云端永远只有 L2；L1 永远在你手上。
L4 是不可消除的已知损失，但因只含 L2，损失被限定在加工后的信息量。

---

## 4. 演进方向（详见 RFC-001 §3）

| Phase | 目标 |
|---|---|
| **1** | 主权数据层——数据开始在本机积累 |
| **2** | 主权数据包——可打包、可加密、可迁移 |
| **3** | 本地模型读取——**先 RAG 后微调**，减少云端依赖 |
| **4** | 自主闭环（远期，仅预留接口，不做承诺） |

**关键技术判断**：Phase 3 采用「先 RAG 后微调」——
RAG 无需训练、数据即时生效、稀疏期也有效；微调需数据积累且是静态快照。

## 5. 必须诚实接受的局限

| 局限 | 说明 |
|---|---|
| **本地泄露的"浓缩性"** | 本地存的是高度浓缩的完整画像，一旦被入侵，价值密度高于单次对话。量级仍远小于云端，可通过加密缓解，但非零 |
| **"机器被控"应用层无解** | at-rest 加密防的是设备丢失/文件外传，防不了机器被控后密钥同失 |
| **加密与检索的矛盾** | ✅ **已由冷热分离化解**：使用中的数据不加密（可检索、本地模型可读），归档数据加密打包（静态保护）。代价是热层明文 ⇒ 机器被控时近期数据可读，建议开启 OS 全盘加密 |
| **归档口令丢失** | 归档包用口令派生密钥 ⇒ **口令丢失 = 归档数据不可恢复**。须在 UX 强提示并提供口令提示 |
| **本地模型能力有限** | 不能替代云端做复杂推理；定位为"个性化/记忆检索"用途 |
