fix(worker): 修复任务永久挂起 + 超时预算死锁

用户发消息后聊天永久无响应。定位出两个独立缺陷。

═══ 缺陷 1：非法 state 导致 SSE 永久挂起（致命）═══

slow-worker-loop / execute-worker-loop 写入了非法状态：
    updateState(id, "running" as TaskState)
"running" 是 task_commands.status 的值，不属于 task_archives.state
（TaskState 枚举：new/clarifying/delegated/executing/waiting_result/
synthesizing/completed/failed/cancelled/timed_out）。
as TaskState 强转绕过编译期检查，问题带到了生产。

而两道消费方都用「活跃态白名单」判定：
    · SSE poller 进度/安抚   → executing/delegated/waiting_result/synthesizing
    · SSE poller 硬超时兜底  → 同上 4 个
    · task-watchdog 扫描     → executing/waiting_result/delegated/synthesizing
"running" 全部不命中，于是任务：
    · 收不到任何进度/安抚事件（前端完全静默）
    · 永不被识别为终态
    · 连硬超时都跳过 → SSE 流永久挂起，用户无限等待

修复（反转逻辑，而非扩充白名单）：
    定义 TERMINAL_TASK_STATES，判定改为「非终态即活跃」。
    任何未知/非法状态一律按活跃处理，最终必被硬超时兜底。
    从此这一类 bug 不可能再导致永久挂起。

附带加固：
    · 两处 worker 写入改为正确的 "executing"，去掉 as 强转
    · 移除其余 3 处无必要的 as TaskState（"failed"/"cancelled"）
    · TaskArchiveRepo.updateState 增加写入边界校验，非法值打显式 ERROR
    · 新增 scripts/verify-task-state-lifecycle.mts（21 条断言）锁住契约

验证（真实请求「帮我写一个光线折射的科普网页」）：
    修复前：first event NEVER，terminal NEVER —— 完全静默、永不结束
    修复后：first event 0s，事件 thinking/status/worker_status/progress/
            error/done 正常流动，302s 正常超时终止  ✅

═══ 缺陷 2：任务级与调用级超时预算相等（必然失败）═══

.env 曾为 SiliconFlow 延迟延长了超时，但漏了 TASK_HARD_TIMEOUT_MS：
    WORKER_TIMEOUT_MS      = 300000  (5min，单次模型调用预算)
    TASK_HARD_TIMEOUT_MS   = 未设置 → 默认 300000 (5min，任务总预算)
    DELEGATED_TASK_TIMEOUT = 600000  (不可达的死配置)

单次模型调用吃光整个任务预算，再算上排队/构造 prompt/egress/验证/写库
开销，任务必然在模型调用完成前被 checkTimeout 杀掉 —— 所有委托任务
100% 失败。

修复：
    · .env 增加 TASK_HARD_TIMEOUT_MS=420000（300s 调用 + 120s 开销余量）
    · model-gateway 启动时校验两条不变量：
        TASK_HARD_TIMEOUT_MS 必须严格大于 WORKER_TIMEOUT_MS
        TASK_SOFT_TIMEOUT_MS 必须小于 TASK_HARD_TIMEOUT_MS
      （不校验 DELEGATED_TASK_TIMEOUT_MS：它只用于 manager-route 的
        delegated_task 路径，不受任务看门狗约束，比了只会误报）
    · 为 DEFAULT_MAX_TOKENS 建立可配置项（默认 2560，env: PROVIDER_MAX_TOKENS）
      原硬编码 4096 在实测中超出 provider 可完成范围：
        max_tokens  耗时
        500         13s   ✅
        1200        22s   ✅
        2500        109s  ✅ finish=stop
        4096        >400s ❌ 永不完成（非流式 307s 断开；流式 400s 未完）

验证：npm run verify:trust 322 条断言全绿（含新增 21 条）
     启动日志无 provider-config 告警，超时配置一致

注：撰写本 commit 时 provider 正处于限流状态（连 mt=800 也需 >300s，
     而最小请求 1s 正常），属临时环境问题，非代码缺陷。
